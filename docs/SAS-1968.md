## Historical objective-v3 primitive and compositional fitting
The following fitting record describes the historical objective-v3 experiment from task `task-0005`; it is retained as historical evidence, not as the current optimizer configuration. That experiment used topology-aware soft component assignment, outlier ownership, skeleton-derived ordered centerline traces, monotone correspondence, bidirectional geometric residuals, and bounded occurrence transforms. Its optimizer ran staged translation, scale, shared-shape, and joint phases with coarse-to-fine samples, deterministic restarts, and robust TRF least squares.

The historical v3 run used objective version 3 and `centerline-em-trf`. The checked-in configuration is now objective v4 with `spline-annealed-alt-lsq`, described above. Family fitting uses fit-split samples for parameter selection; validation and hold-out samples are diagnostic and do not update parameters or select restarts.

The commands below are the current entry points and read the checked-in fit configuration. A new invocation therefore uses objective v4; it does not reproduce the historical objective-v3 reports described in this section.

```sh

  work/sas-1968/sources/sas-1968-01-alphabet-plate.png \
  --layout examples/layouts/sas-1968-alphabet.yaml \
  --output work/sas-1968/observations/alphabet
python -m tools.ingest_sas_sources
```

The 63 label assignments were visually inspected in the extraction review:
uppercase A through Z, lowercase a through z plus ß (in the plate's order),
and digits 1 through 9 followed by 0. Wide/overlapping capitals, descending
lowercase forms and ß were checked. Label acceptance is not fitting acceptance.
The rectangular extraction regions can contain neighboring ink or intersect
strokes, particularly around O/P/Q and o/p/q. Those samples are explicitly marked
`needs-isolation`; other samples still require fitting review. Gap confidence
is not used to reject a correct label.

Observation IDs are Unicode-based and independent of extraction ordering.
Crop locators are `local-only:` references, not runtime dependencies. The
observation schema checks unique IDs, source references and source bounds.
