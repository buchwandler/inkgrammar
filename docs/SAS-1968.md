## Primitive and compositional fitting

Taskledger task `task-0005` records the current optimization redesign. SAS primitive fitting uses objective v3: topology-aware soft component assignment, outlier ownership, skeleton-derived ordered centerline traces, monotone correspondence, bidirectional geometric residuals, and bounded occurrence transforms. The optimizer runs staged translation, scale, shared-shape, and joint phases with coarse-to-fine samples, deterministic restarts, and robust TRF least squares. Unsupported objective or optimizer settings are rejected by the fit configuration validator.

The SAS `fit-config.yaml` selects objective version 3 and `centerline-em-trf`. Its assignment, centerline, geometry, prior, family-balance, and optimizer settings are the reproducible configuration. Family fitting selects parameters using fit-split samples only. Validation and hold-out samples are evaluated after fitting for diagnostics; they do not update parameters or select restarts.

Run the four documented primitive fits from the repository root when the authorized private materialization is available:

```sh
inkgrammar fit optimize-primitive data/training/sas-1968/project.yaml sas-underturn-01
inkgrammar fit optimize-primitive data/training/sas-1968/project.yaml sas-open-oval-01
inkgrammar fit optimize-primitive data/training/sas-1968/project.yaml sas-ascender-loop-01
inkgrammar fit optimize-primitive data/training/sas-1968/project.yaml sas-hump-01
```

Compact v2 checkpoints and source-free JSON/Markdown reports are written under `data/training/sas-1968/`. The reports separate fit, validation, and hold-out metrics and include assignment confidence, candidate-to-target and target-to-candidate geometry, endpoint, tangent, radius, coverage, optimizer status, and restart outcomes. Private nominal/aligned review sheets are written under `work/sas-1968/overlays/`.

Do not promote a primitive because its aggregate objective decreased. Review every fit occurrence against candidate-to-target p95 ≤ 2 px, target-to-candidate p95 ≤ 2 px, supervised endpoint RMS ≤ 1.5 px, assigned coverage ≥ 0.90, and the visual branch/overlay evidence. The report `data/training/sas-1968/reports/sas-v3-promotion-review.md` records the latest review. None of the four v3 candidates passed all gates, so no primitive was promoted. In particular, the ascender-loop hold-out panels still show a branch/continuation mismatch. Hold-out evidence remains diagnostic and was not used for parameter selection. The seed grammar and compiled SAS model remain unchanged.

The source-free alphabet control sheet does not load scans or materialized crops:

```sh
inkgrammar fit control-sheet data/training/sas-1968/project.yaml \
  --output work/sas-1968/control/alphabet.png
```

It writes a JSON status companion beside the image. Missing and provisional glyphs remain explicit rather than being synthesized. The current sheet renders 12 of 53 requested glyphs because the accepted topology is intentionally incomplete. `--include-digits` adds digits; `--occurrence-deltas` previews per-sample nuisance transforms instead of canonical model state.

Checkpoint format v2 stores accepted parameters, compact progress, and trace summaries, not per-evaluation parameter snapshots or source imagery. Loading a v1 checkpoint migrates it in memory while preserving its accepted parameters. The one-shot migration for the four committed SAS checkpoints is `python -m tools.migrate_fit_checkpoints`; it has already been run for this project.

Corpus `active_instances` lists the topology instances that participate in each sample's compositional explanation. Glyph fitting keeps shared primitive geometry fixed and writes occurrence-fit reports and composition overlays under `work/sas-1968/glyph-fits/`. Run glyph fitting and word diagnostics from the repository root:

```sh
inkgrammar fit fit-glyphs data/training/sas-1968/project.yaml
inkgrammar fit validate-words data/training/sas-1968/project.yaml
```

Word validation is diagnostic only. Word samples identify active instances as `character-index:instance-id`. The validator composes fitted glyph occurrences at their declared advance widths, reports within-glyph attachment gaps, and marks glyph-boundary connections as unspecified when no contextual rule is present. It does not optimize parameters. The current SAS fitting corpus contains no word samples, so `validate-words` produces no reports for SAS until reviewed word observations are added.

Private source scans, crops, masks, distance fields, skeleton artifacts, and generated review/control images must remain under ignored `work/`. Do not copy them into source-free reports or commit them. The authorized source materialization is private and is not a runtime dependency of the control-sheet command.

Reproduce ingestion from the supplied bundle, from the repository root:

```sh
inkgrammar page extract \
  work/sas-1968/sources/sas-1968-01-alphabet-plate.png \
  --layout examples/layouts/sas-1968-alphabet.yaml \
  --output work/sas-1968/observations/alphabet
python -m tools.ingest_sas_sources
```

The 63 label assignments were visually inspected in the extraction review:
uppercase A through Z, lowercase a through z plus ß (in the plate's order),
and digits 1 through 9 followed by 0. Wide/overlapping capitals, descending
lowercase forms and ß were checked. Label acceptance is not fitting acceptance.
The rectangular extraction regions can contain neighboring ink or intersect
strokes, particularly around O/P/Q and o/p/q. Those samples are explicitly marked
`needs-isolation`; other samples still require fitting review. Gap confidence
is not used to reject a correct label.

Observation IDs are Unicode-based and independent of extraction ordering.
Crop locators are `local-only:` references, not runtime dependencies. The
observation schema checks unique IDs, source references and source bounds.
